开发者文档 · Account API

账户级 API 文档

面向本地 Agent、自动化脚本与第三方服务的账户级 API Key 接入说明。通过一柄 mhbat_ API Key， 你可以编程式管理自己的 OIDC 接入应用、查看绑定设备并检索审计日志； Key 本身的申请、列表与吊销则在开发者门户中以浏览器操作完成。

Key 即凭据： API Key 等同于你账户的操作权限。明文只在创建时显示一次， 服务端只保存哈希，丢失后只能吊销重建。请像保管密码一样保管它：不要写进源码、Git、日志或聊天窗口。

1. 概述与前置条件

账户级 API 面向两类诉求：一是让本地 Agent / 脚本能代替你在开发者门户完成应用的日常维护； 二是让自动化流程能够自查账户状态（设备、审计）。它与 OIDC 接入指南描述的授权协议互补：OIDC 解决“用户如何授权第三方”，本页解决“开发者如何管理自己的接入配置”。

管理面（浏览器，非 API）

  • 入口：开发者门户「API 密钥」页；
  • 支持申请、查看列表、吊销 Key；
  • 明文 Key 仅创建弹窗显示一次。

API 面（本文档）

  • 全部接口使用 Bearer 认证直连 Identity 服务；
  • 覆盖应用 CRUD、回调、scope、审核、凭据与审计；
  • 适合本地 Agent、CI 脚本与第三方服务调用。

前置条件

  1. 拥有 Mini-HBUT 账号，并能登录开发者门户；
  2. 在门户「API 密钥」页完成一次 Key 申请（见下方步骤）；
  3. 一个能发起 HTTPS 请求的环境（curl / Python / Node 均可）。

申请 API Key 的步骤

  1. 使用浏览器登录 Mini-HBUT Developer Portal；
  2. 在左侧导航进入「API 密钥」页。【截图占位：门户左侧导航中「API 密钥」入口高亮】
  3. 点击「新建密钥」，填写密钥备注名（便于日后辨认用途）并确认。【截图占位：新建密钥弹窗表单】
  4. 创建成功后，页面弹出完整明文 Key。它只显示这一次，立即整串复制到你的密码管理器或秘密存储。【截图占位：明文 Key 弹窗，Key 值打码】
  5. 关闭弹窗后列表中只会显示 Key 的前缀与元信息；如果明文丢失，只能吊销后重新申请。

2. 认证方式

Key 形态

API Key 的固定格式为 mhbat_<8位hex>_<43位base64url>， 例如下面这串仅为格式示意，并非真实凭据：

mhbat_ab12cd34_AbCdEfGhIjKlMnOpQrStUvWxYz0123456789AbCdEfG
  • 前缀 mhbat_ + 8 位十六进制前缀段 + 43 位 base64url 主体，整串一起参与认证；
  • 认证时携带整串 Key，不要截断、拆分或只发送某一段；
  • 服务端数据库只保存 Key 的哈希，泄露数据库也无法还原明文。

请求头格式

所有账户级接口都需要携带如下请求头：

Authorization: Bearer <整串Key>

服务域名

账户级 API 与 OIDC 同域部署。与 OIDC 接入指南 的口径一致： 中文域名 id.湖北工业大学.com 只适合人类展示；代码、配置与环境变量统一使用下面的 ASCII / Punycode canonical 形式：

https://id.xn--vhq74jc2fzpchter27a.com

保管与泄露处置

  • Key 存放在环境变量或秘密管理器中，运行时注入进程；
  • 不要把 Key 提交进 Git、打印进日志、放进前端代码或截图分享；
  • 不同用途使用不同的 Key（一柄 Key 一个用途），便于单独吊销而不影响其它流程；
  • 疑似泄露立即处理：① 到开发者门户吊销该 Key；② 通过审计接口排查异常调用；③ 申请新 Key；④ 更新所有使用该 Key 的部署。
注意区分两套 Bearer 凭据：本页的 mhbat_ API Key 用于调用账户级管理 API； OIDC 流程中的 Access Token 用于调用 UserInfo 等协议端点。两者不可互换使用。

3. 快速开始：5 分钟 curl 序列

下面用一个连续的 curl 序列走完「验 Key → 建应用 → 配回调/scope → 提交审核」的最短路径。 所有响应 JSON 均为示意结构，字段以服务端实际返回为准。

步骤 0：准备环境变量

# 1) 登录开发者门户，进入「API 密钥」页创建 Key；
#    创建成功弹窗中的明文 Key 仅显示这一次，立即整串复制保存。
# 2) 在终端导出两个环境变量（示例 Key 为占位，请替换为自己的）：
export API_BASE="https://id.xn--vhq74jc2fzpchter27a.com"
export MHBAT_KEY="mhbat_ab12cd34_AbCdEfGhIjKlMnOpQrStUvWxYz0123456789AbCdEfG"

步骤 1：Key 自检（me）

curl -sS "\$API_BASE/api/v1/account/me" \
  -H "Authorization: Bearer \$MHBAT_KEY"
{
  "user_id": "usr_7f3a9c21",
  "key": {
    "name": "my-local-agent",
    "prefix": "mhbat_ab12cd34",
    "created_at": "2026-08-20T08:00:00Z",
    "expires_at": null,
    "last_used_at": "2026-08-23T12:34:56Z"
  }
}

响应为示意。拿到 user_id 即说明 Key 有效且归属正确。

步骤 2：列出已有应用

curl -sS "\$API_BASE/api/v1/account/apps" \
  -H "Authorization: Bearer \$MHBAT_KEY"
{
  "apps": [
    {
      "id": "app_01j8zkm3v6n7",
      "name": "成绩提醒机器人",
      "app_type": "native_public",
      "status": "active",
      "client_id": "cl_9p2m4k8s",
      "redirect_uris": ["http://127.0.0.1/callback"],
      "scopes": ["openid", "profile"],
      "created_at": "2026-07-01T02:10:00Z",
      "updated_at": "2026-07-01T02:10:00Z"
    }
  ]
}

响应为示意。首次接入时 apps 可能为空数组。

步骤 3：创建应用（draft）

curl -sS -X POST "\$API_BASE/api/v1/account/apps" \
  -H "Authorization: Bearer \$MHBAT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
        "name": "我的第一个接入应用",
        "app_type": "web_confidential",
        "description": "在学习计划网站展示课程与成绩提醒"
      }'
{
  "app": {
    "id": "app_x1y2z3w4",
    "name": "我的第一个接入应用",
    "app_type": "web_confidential",
    "status": "draft",
    "client_id": "cl_a1b2c3d4",
    "redirect_uris": [],
    "scopes": [],
    "created_at": "2026-08-23T12:40:00Z",
    "updated_at": "2026-08-23T12:40:00Z"
  }
}

响应为示意。新应用处于 draft 状态，可以自由修改。

步骤 4：配置回调与 scopes

# 记下上一步响应中的 app.id（此处假设为 app_x1y2z3w4）
APP_ID="app_x1y2z3w4"

# 新增回调地址（web_confidential 只允许 https，精确匹配）
curl -sS -X POST "\$API_BASE/api/v1/account/apps/\$APP_ID/redirect-uris" \
  -H "Authorization: Bearer \$MHBAT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"redirect_uri": "https://my-app.example.com/oauth/callback"}'

# 配置 scope 白名单（PUT 为全量替换语义）
curl -sS -X PUT "\$API_BASE/api/v1/account/apps/\$APP_ID/scopes" \
  -H "Authorization: Bearer \$MHBAT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"scopes": ["openid", "profile"]}'
{
  "redirect_uri": {
    "id": "ruri_5f6g7h8i",
    "uri": "https://my-app.example.com/oauth/callback",
    "created_at": "2026-08-23T12:42:00Z"
  }
}

{
  "app": {
    "id": "app_x1y2z3w4",
    "scopes": ["openid", "profile"],
    "updated_at": "2026-08-23T12:43:00Z"
  }
}

两条命令的响应均为示意。web_confidential 的回调必须是 https 且与授权请求精确匹配。

步骤 5：提交人工审核

curl -sS -X POST "\$API_BASE/api/v1/account/apps/\$APP_ID/submit" \
  -H "Authorization: Bearer \$MHBAT_KEY"
{
  "app": {
    "id": "app_x1y2z3w4",
    "status": "pending_review",
    "submitted_at": "2026-08-23T12:45:00Z"
  }
}

响应为示意。提交后状态变为 pending_review；审核通过并启用后应用才会进入 active，被 OIDC 动态加载。

Windows 用户提示：以上命令适用于 bash / zsh。PowerShell 中请使用 curl.exe， 或直接使用第 6 节的 Python / Node 封装类，体验更好。

4. 端点参考

所有端点均要求 Authorization: Bearer <整串Key>，基址为 https://id.xn--vhq74jc2fzpchter27a.com。除非特别说明，请求与响应体均为 JSON。 除每个端点列出的特有错误外，任何端点都可能返回第 5 节的通用错误 （401 / 403 / 400 / 429 / 500）。响应示例均为示意。

GET/api/v1/account/me

Key 自检

验证当前 Key 是否有效，并返回所属 user_id 与 Key 元信息。推荐作为启动时的健康检查第一步。

本端点无必填参数。

请求示例
curl -sS "\$API_BASE/api/v1/account/me" \
  -H "Authorization: Bearer \$MHBAT_KEY"
响应示例（示意）
{
  "user_id": "usr_7f3a9c21",
  "key": {
    "name": "my-local-agent",
    "prefix": "mhbat_ab12cd34",
    "created_at": "2026-08-20T08:00:00Z",
    "expires_at": null,
    "last_used_at": "2026-08-23T12:34:56Z"
  }
}
特有错误情形
  • 401 API_KEY_INVALID — Key 不存在或格式错误；核对整串 Key（含 mhbat_ 前缀）后重试
  • 403 API_KEY_REVOKED — Key 已吊销；重新申请 Key
  • 403 API_KEY_EXPIRED — Key 已过期；重新申请 Key

POST/api/v1/account/apps

创建应用

创建一个新的 OIDC 接入应用，初始状态为 draft。web_confidential 应用的 client_secret 通过 credentials/rotate 生成，仅显示一次。

参数位置类型必填说明
namebodystring是应用显示名称
app_typebodystring是应用类型：web_confidential（服务端持密）或 native_public（公共客户端）
descriptionbodystring否用途描述，有助于加快人工审核
请求示例
curl -sS -X POST "\$API_BASE/api/v1/account/apps" \
  -H "Authorization: Bearer \$MHBAT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
        "name": "我的第一个接入应用",
        "app_type": "web_confidential",
        "description": "在学习计划网站展示课程与成绩提醒"
      }'
响应示例（示意）
{
  "app": {
    "id": "app_x1y2z3w4",
    "name": "我的第一个接入应用",
    "app_type": "web_confidential",
    "status": "draft",
    "client_id": "cl_a1b2c3d4",
    "redirect_uris": [],
    "scopes": [],
    "created_at": "2026-08-23T12:40:00Z",
    "updated_at": "2026-08-23T12:40:00Z"
  }
}
特有错误情形
  • 400 参数错误 — 缺少 name / app_type 或取值非法；按 message 修正请求体

修改应用信息

更新应用名称、描述等基础信息。处于 pending_review 等锁定状态时可能被拒绝。

参数位置类型必填说明
:idpathstring是应用 id
namebodystring否新的应用名称
descriptionbodystring否新的用途描述
请求示例
curl -sS -X PATCH "\$API_BASE/api/v1/account/apps/\$APP_ID" \
  -H "Authorization: Bearer \$MHBAT_KEY" \
  -H "Content-Type: application/json" \

响应示例（示意）
{

DELETE/api/v1/account/apps/:id

删除应用

删除名下应用。已进入审核流程或运行中的应用通常不允许直接删除，需先 revoke。

参数位置类型必填说明
:idpathstring是应用 id
请求示例
curl -sS -X DELETE "\$API_BASE/api/v1/account/apps/\$APP_ID" \
  -H "Authorization: Bearer \$MHBAT_KEY"
响应示例（示意）
HTTP/1.1 204 No Content
特有错误情形
  • 400 参数错误 — 当前状态不允许删除；先执行 revoke 再删除
  • 404 资源不存在 — 应用不存在或不属于你；核对 id
POST/api/v1/account/apps/:id/redirect-uris

新增回调地址

为应用登记一条 Redirect URI。服务端会按 app_type 校验规则，并在授权时做精确匹配。

参数位置类型必填说明
:idpathstring是应用 id
redirect_uribodystring是回调地址。web_confidential 仅允许 https；native_public 允许自定义 scheme 与 http://127.0.0.1 回环；禁止通配符与 fragment
请求示例
curl -sS -X POST "\$API_BASE/api/v1/account/apps/\$APP_ID/redirect-uris" \
  -H "Authorization: Bearer \$MHBAT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"redirect_uri": "https://my-app.example.com/oauth/callback"}'
响应示例（示意）
{
  "redirect_uri": {
    "id": "ruri_5f6g7h8i",
    "uri": "https://my-app.example.com/oauth/callback",
    "created_at": "2026-08-23T12:42:00Z"
  }
}
特有错误情形
  • 400 参数错误 — URI 不符合 app_type 规则（http、通配符、fragment 等）；按规则调整后重试
  • 404 资源不存在 — 应用不存在或不属于你；核对 id
DELETE/api/v1/account/apps/:id/redirect-uris/:rid

移除回调地址

按回调记录 id 移除一条已登记的 Redirect URI。

参数位置类型必填说明
:idpathstring是应用 id
:ridpathstring是回调记录 id，形如 ruri_5f6g7h8i
请求示例
curl -sS -X DELETE "\$API_BASE/api/v1/account/apps/\$APP_ID/redirect-uris/ruri_5f6g7h8i" \
  -H "Authorization: Bearer \$MHBAT_KEY"
响应示例（示意）
HTTP/1.1 204 No Content
特有错误情形
  • 404 资源不存在 — 应用或回调记录不存在 / 不属于你；核对 id
PUT/api/v1/account/apps/:id/scopes

配置 scope 白名单

全量替换应用的 scope 白名单。白名单只能从平台支持的 scope 中选择；包含 student.identity 时必须附带用途说明（不少于 10 个字），经人工审核通过后方可实际使用。

参数位置类型必填说明
:idpathstring是应用 id
scopesbodystring[]是scope 数组，取值见白名单：openid / profile / student.identity / offline_access
purposebodystring条件申请 student.identity 时的用途说明，长度不少于 10 个字
请求示例
curl -sS -X PUT "\$API_BASE/api/v1/account/apps/\$APP_ID/scopes" \
  -H "Authorization: Bearer \$MHBAT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
        "scopes": ["openid", "profile", "student.identity"],
        "purpose": "在本站展示已验证的学生身份徽章"
      }'
响应示例（示意）
{
  "app": {
    "id": "app_x1y2z3w4",
    "scopes": ["openid", "profile", "student.identity"],
    "scope_review": {
      "student.identity": "pending_review"
    },
    "updated_at": "2026-08-23T13:00:00Z"
  }
}
特有错误情形
  • 400 参数错误 — scope 不在白名单内，或 student.identity 缺少合规用途说明；补全 purpose（≥10 字）后重试
  • 404 资源不存在 — 应用不存在或不属于你；核对 id

POST/api/v1/account/apps/:id/submit

提交审核

把 draft 状态的应用提交人工审核，状态流转为 pending_review。提交前至少应配置一条合法回调与必要的 scope。

参数位置类型必填说明
:idpathstring是应用 id

6. 本地 Agent 接入指南

设计原则

  • 最小权限：只申请业务真正需要的 scope；一柄 Key 只服务一个用途，出问题时可以精准吊销；
  • 超时：每次请求都必须显式设置连接与读取超时（建议 10s 量级），绝不无限等待；
  • 重试：只自动重试幂等请求（GET / PUT / DELETE）。POST 可能产生副作用（创建、提交、轮换）， 重试前先确认上一请求是否已生效；重试采用指数退避并加入随机抖动，设次数上限；
  • 429 处理：收到 RATE_LIMITED 后解析 Retry-After 头并原样等待， 不要自作主张缩短间隔，更不要并发轰炸；
  • fail closed：遇到 401 / 403 时停止使用当前 Key 继续尝试，先排查再行动。

Python（requests）封装示例

import os
import time

import requests


class HbutApiError(Exception):
    """账户级 API 业务错误：携带 HTTP 状态码与服务端 error code。"""

    def __init__(self, status: int, code: str, message: str):
        super().__init__("[" + str(status) + "] " + code + ": " + message)
        self.status = status
        self.code = code
        self.message = message


class HbutAccountClient:
    """Mini-HBUT 账户级 API 最小封装。

    设计原则：
    - 自动携带 Authorization: Bearer <整串 Key>
    - 显式超时，绝不无限等待
    - 只自动重试幂等方法；429 严格遵循 Retry-After
    """

    MAX_RATE_RETRIES = 3    # 429 本地重试上限
    MAX_SERVER_RETRIES = 3  # 500 指数退避重试上限

    def __init__(self, base_url: str, api_key: str, timeout: float = 10.0):
        if not api_key.startswith("mhbat_"):
            raise ValueError("API Key 必须是完整的 mhbat_ 整串 Key")
        self.base_url = base_url.rstrip("/")
        self.api_key = api_key
        self.timeout = timeout
        self.session = requests.Session()
        self.session.headers.update({
            "Authorization": "Bearer " + api_key,
        })

    def request(self, method: str, path: str, payload=None):
        url = self.base_url + path
        rate_retries = 0
        server_retries = 0
        while True:
            resp = self.session.request(
                method, url, json=payload, timeout=self.timeout,
            )
            if resp.status_code == 429:
                if rate_retries >= self.MAX_RATE_RETRIES:
                    raise HbutApiError(429, "RATE_LIMITED", "超过本地重试上限")
                # 严格遵循服务端 Retry-After（秒）
                wait = float(resp.headers.get("Retry-After", "1"))
                time.sleep(wait)
                rate_retries += 1
                continue
            if resp.status_code == 500 and method in ("GET", "PUT", "DELETE"):
                if server_retries >= self.MAX_SERVER_RETRIES:
                    break
                time.sleep(0.5 * (2 ** server_retries))  # 指数退避 0.5s/1s/2s
                server_retries += 1
                continue
            break

        if resp.status_code >= 400:
            try:
                body = resp.json()
            except ValueError:
                body = {}
            raise HbutApiError(
                resp.status_code,
                body.get("error", "UNKNOWN"),
                body.get("message", ""),
            )
        if resp.status_code == 204:
            return None
        return resp.json()

    def get(self, path: str):
        return self.request("GET", path)

    def post(self, path: str, payload=None):
        return self.request("POST", path, payload)

    def patch(self, path: str, payload=None):
        return self.request("PATCH", path, payload)

    def delete(self, path: str):
        return self.request("DELETE", path)


if __name__ == "__main__":
    client = HbutAccountClient(

    )

Node（原生 fetch）封装示例

// hbut-client.mjs — Node 18+ 原生 fetch，零依赖
const BASE_URL = 'https://id.xn--vhq74jc2fzpchter27a.com';

export class HbutApiError extends Error {
  constructor(status, code, message) {
    super('[' + status + '] ' + code + ': ' + message);
    this.status = status;
    this.code = code;
  }
}

export class HbutAccountClient {
  constructor({ apiKey, baseUrl = BASE_URL, timeoutMs = 10000 }) {
    if (!apiKey || !apiKey.startsWith('mhbat_')) {
      throw new Error('API Key 必须是完整的 mhbat_ 整串 Key');
    }
    this.baseUrl = baseUrl;
    this.apiKey = apiKey;
    this.timeoutMs = timeoutMs;
  }

  async request(method, path, payload) {
    const headers = { Authorization: 'Bearer ' + this.apiKey };
    let body;
    if (payload !== undefined) {
      headers['Content-Type'] = 'application/json';
      body = JSON.stringify(payload);
    }

    let serverRetries = 0;
    for (;;) {
      const resp = await fetch(this.baseUrl + path, {
        method,
        headers,
        body,
        signal: AbortSignal.timeout(this.timeoutMs), // 显式超时
      });

      if (resp.status === 429) {
        // 严格遵循服务端 Retry-After（秒）；生产请再加本地重试上限
        const retryAfter = Number(resp.headers.get('Retry-After') ?? '1');
        await sleep(retryAfter * 1000);
        continue;
      }
      if (resp.status === 500 && method !== 'POST' && serverRetries < 3) {
        // 指数退避 0.5s/1s/2s，仅针对幂等方法
        await sleep(500 * 2 ** serverRetries);
        serverRetries += 1;
        continue;
      }
      if (resp.status >= 400) {
        const data = await resp.json().catch(() => ({}));
        throw new HbutApiError(resp.status, data.error ?? 'UNKNOWN', data.message ?? '');
      }
      if (resp.status === 204) return null;
      return resp.json();
    }
  }

  get(path) { return this.request('GET', path); }
  post(path, payload) { return this.request('POST', path, payload); }
  patch(path, payload) { return this.request('PATCH', path, payload); }
  delete(path) { return this.request('DELETE', path); }
}

const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

常见陷阱

  • 复制 Key 时漏掉尾部字符或混入空格、引号 → 401 API_KEY_INVALID；
  • 把 Key 写进源码、Dockerfile、Git 历史或异常日志 → 视同泄露，应立即吊销重建；
  • 未设置超时 → 网络抖动时 Agent 进程挂死、任务队列堆积；
  • 对 400 / 401 / 403 / 404 盲目重试 → 这些是非暂时性错误，重试只会浪费配额；
  • 忽略 Retry-After 固定频率猛刷 → 限流窗口不断延长；
  • 把 API Key 当 OIDC Access Token 调 UserInfo（或反过来）→ 两套凭据体系互不通用；
  • Redirect URI 使用通配符、fragment 或随意端口 → 会被校验拒绝；native_public 回环仅允许 http://127.0.0.1；
  • 申请 student.identity 时未填写不少于 10 个字的用途说明 → 审核被退回；
  • 应用还没走到 active 就去跑 OIDC 授权 → 只有 active 应用才会被动态加载；
  • credentials/rotate 后忘记同步更新服务端 secret → 旧 secret 立即失效，授权交换开始报错；
  • 把 revoke 当作“临时停用” → revoked 是终态不可恢复，临时停用请关注 suspended 状态。

7. 应用状态机与审核说明

              POST .../submit           人工审核通过             启用
   draft ────────────────────▶ pending_review ────────────▶ approved ────────────▶ active
     ▲                              │                                              │
     │ 修改后重新 submit              │ 人工审核拒绝                                   │ 平台侧操作
     │                              ▼                                              ▼
     └────────────────────────── rejected                             suspended / revoked
                                                                       (revoked 为终态)
状态含义允许的操作
draft刚创建，自由编辑阶段修改信息、配置回调与 scope、提交审核、删除
pending_review已提交，等待人工审核等待审核结论，不宜再改动
approved审核通过，尚未启用启用进入 active
active运行中，被 OIDC 动态加载，可正常参与授权流程日常运维：轮换凭据、查审计、吊销
suspended被平台侧暂停（如违规、风控）暂停授权能力；按平台指引处理后恢复或吊销
rejected审核拒绝按反馈修改后可重新 submit 进入 pending_review
revoked已吊销（终态）不可恢复；如需继续接入请新建应用

关键规则：仅 active 应用会被 OIDC 动态加载。 suspended / revoked 的应用会立即失去授权能力；rejected 不是终点，按审核意见修改后重新提交即可。 审核由人工完成，涉及 student.identity 等敏感 scope 时会额外核对用途说明。

8. 安全须知与审计

  • 服务端只存 Key 哈希，明文仅创建时显示一次；任何声称能“找回明文 Key”的都是假的；
  • 所有 Key 操作与应用变更都会进入审计日志，可通过应用级与账户级 audit 端点查询；
  • 审计事件 metadata 不存任何密钥材料，日志可以放心留存与导出分析；
  • 建议定期（例如每月）检查账户级 audit 与 devices 列表，确认没有陌生设备与异常操作；
  • 发现未知的 Key、应用或设备：先吊销 / 吊销应用 / 排查设备，再排查自身环境是否失陷；
  • 轮换是常态：web_confidential 凭据定期 rotate；长期不用的 Key 及时在门户吊销；
  • Agent 的日志系统必须脱敏：禁止记录 Authorization 头、Key 明文、client_secret 与审计之外的敏感字段。
泄露应急处置口诀：吊销 → 查审计 → 重建 → 更新部署。 四步都可以在一小时内完成，越早吊销影响越小。
