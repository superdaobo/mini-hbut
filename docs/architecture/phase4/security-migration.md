# 阶段 4E：凭据、Token 与备份加密迁移

## 新写入规则

- 密码只写系统密钥环；密钥环不可用时明确不持久化，不再回退 Base64。
- Cookie、OneCode Token、Refresh Token 使用 `mhbsec:v1:` 版本化信封。
- 每个学号使用独立的 256 位主密钥，主密钥只存在系统密钥环。
- 信封使用随机 IV、AES-256-CBC 加密和独立派生密钥的 HMAC-SHA256 完整性认证。
- 忘记 HBUT 账号时同步删除密码和该账号的敏感字段主密钥。

## 显式迁移

`init_db` 不再扫描或改写真实用户凭据。旧数据迁移必须由上层在取得用户明确确认后调用：

1. 创建回滚备份；
2. 调用 `migrate_session_passwords_v2` 将旧 Base64 密码迁入密钥环；
3. 调用 `migrate_session_secrets_v1` 加密 Cookie 与 Token；
4. 重新读取并验证会话；
5. 成功后保留旧备份至用户确认。

迁移函数幂等；无法取得密钥环时保留旧数据并报告失败，不会写入明文替代品。旧明文字段仅保留只读兼容，必须通过显式迁移才会重写。

## 加密备份与恢复

- `backup_database_encrypted` 生成 `.mhbbackup`，包含版本头和认证标签。
- 明文 SQLite 仅在随机 staging 目录短暂存在，函数结束时清理。
- 正式命名前会立即认证解密；损坏数据不会落地。
- `restore_encrypted_backup` 只允许恢复到不存在的新路径，认证、解密并通过 SQLite integrity_check 后才原子命名，绝不覆盖正式库。

## 回滚

回滚迁移时关闭应用，将已验证的迁移前备份恢复到新路径，人工核对后再进行受控切换。禁止脚本静默覆盖正在使用的数据库。

## 日志边界

日志只记录字段名、学号范围与错误类别，不记录密码、Cookie、Token、主密钥或信封内容。
