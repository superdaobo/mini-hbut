# OIDC 前端页面设计需求文档（auth.* 站点）

> 版本：2026-08-15
> 用途：由你（设计者）独立完成视觉设计；设计完成后把 CSS 交给我，我直接替换/覆盖 `identity-platform/web/app/globals.css` 应用。
> 本文只规定「每个页面必须有什么功能、包含什么元素、有哪些约束」，不限制视觉风格。

---

## 一、范围与总体说明

需要重新设计的页面（全部位于 `identity-platform/web`，部署在 `auth.湖北工业大学.com`）：

| # | 页面 | 路由 | 性质 |
|---|------|------|------|
| 1 | **授权接力页**（核心页面） | `/r/<request_id>` | 用户扫码/点按钮登录的主页面，含 10 种状态 |
| 2 | **帮助页** | `/help` | 无法打开 App 时的排障说明 |
| 3 | **回调页**（测试用） | `/callback` | 测试授权完成后展示授权码 |
| 4 | 站点框架 | 所有页面共用 | Header + Footer + 全局底色 |

**设计原则（必须遵守）**：

1. **移动端优先**：大部分用户用手机扫码/点链接，页面在 360px 宽也须完整可用；桌面端居中窄卡（现约 480px）。
2. **信任感与安全感优先**：这是登录授权页，不是营销页。视觉应克制、可信，避免花哨动效影响"我在向第三方授权"的严肃感。
3. **状态可感知**：授权流程有加载中/等待/成功/失败/过期等多种状态，必须让用户一眼看出当前处于哪一步、接下来该做什么。
4. **可访问性**：文字与背景对比度 ≥ WCAG AA；交互元素必须有清晰的 focus 样式；状态不只靠颜色区分（已有符号前缀，可强化）。
5. **零外部依赖**：不引用外部图片/CDN/字体（CSP 限制）；二维码必须本地渲染（现状已满足）。

## 二、站点框架（所有页面共用）

### 2.1 Header（`auth-header`）

**功能**：表明"这是 Mini-HBUT 身份服务"，不是学校官方页面。

**元素**：

| 元素 | 现有类名 | 说明 |
|------|---------|------|
| 品牌名 | `.auth-brand` | 文案固定「Mini-HBUT Identity」，建议配一个图形 logo（可用内联 SVG） |
| 副标题 | `.auth-subtitle` | 文案固定「使用 Mini-HBUT 完成登录」 |

### 2.2 Footer（`.disclaimer`，根布局全局）

**功能**：非官方声明，全站所有页面底部必须出现（安全合规要求）。

**元素**：

| 元素 | 现有类名 | 说明 |
|------|---------|------|
| 声明文本 | `.disclaimer` | 文案固定「Mini-HBUT 为第三方学生开发工具，本服务不是湖北工业大学官方统一身份认证服务。」 |

### 2.3 全局底色 / 字体

- `body` 背景、主文字色、辅助文字色、卡片色、边框色、强调色、危险色
- 建议用 CSS 变量（现已有 `--bg/--card/--text/--muted/--border/--accent/--danger`），且**必须同时提供浅色 + 深色两套**（`prefers-color-scheme: dark`，现有已支持）
- 中文字体栈保持系统字体（PingFang SC / Microsoft YaHei），不建议加载 webfont

## 三、页面 1：授权接力页 `/r/<request_id>`（核心）

**页面职责**：展示"哪个应用在请求什么权限" → 引导用户去 App 确认 → 轮询等待结果 → 跳回原应用。
**安全边界（代码已固定，设计不能破坏）**：

- 页面上**没有**允许/拒绝按钮（批准只能在 App 内完成）；
- 页面不展示任何密码输入框；
- 不显示学号/姓名等个人信息（`request-card` 只显示应用信息，不显示用户信息）。

### 3.1 整体布局（`.auth-flow`）

单一窄列，从上到下依次为：

```
[应用卡片]  ← 请求方是谁、要什么权限（最重要，视觉最重）
[倒计时]    ← 请求有效期
[打开 App 按钮] ← 主操作（移动端优先可见）
[二维码]    ← 桌面端扫描（移动端可折叠）
[状态横幅]  ← 当前进度提示
```

### 3.2 元素 A：请求方应用卡片（`.app-card`）

**功能**：回答用户两个问题——"谁在请求登录？"、"他要我的什么信息？"
**防钓鱼要求（硬性）**：应用主页域名必须显著展示，不能只显示应用名。

| 元素 | 现有类名 | 说明 |
|------|---------|------|
| 测试横幅（可选） | `.test-banner` | 仅测试应用出现：🧪 测试应用，不会获取真实数据（红色/黄色醒目系） |
| 应用名 | `.app-name` | 一级标题，应用展示名 |
| 应用主页 | `.app-meta-row` 内 `dt=应用主页 dd=hostname` | 域名，建议等宽字体、可复制 |
| 开发者 | `.app-meta-row` 内 `dt=开发者 dd=名称` | |
| 审核状态徽章 | `.review-badge` + `.review-verified/.review-pending/.review-rejected` | 三种状态三种配色（绿/黄/红），圆角小标签 |
| 权限标题 | `.scope-title` | 「请求的权限」 |
| 权限列表 | `.scope-list` > `.scope-item`（`span.scope-label` + 可选 `span.risk-tag`） | 每条权限一行；「敏感」权限加红色小标签 |
| 权限说明 | `.scope-note` | 「本页面仅作说明，允许/拒绝按钮只存在于 Mini-HBUT App 内」 |

**设计建议**：卡片内可加入应用图标占位（当前无图标字段，可先做通用图标或图标位）。

### 3.3 元素 B：倒计时（`.countdown`）

**功能**：告知请求有效期，防止用户误以为可以无限等待。

| 元素 | 现有类名 | 说明 |
|------|---------|------|
| 倒计时文本 | `.countdown` | 「请求将在 N 秒/分 后过期」；最后 30 秒建议变红提醒（现有 `expiryUrgent` 前端变量，可加 class） |

### 3.4 元素 C：打开 App 主按钮（`.open-app-btn`）

**功能**：唤起本机 Mini-HBUT App（`minihbut://` 深链）。全页面唯一的"主操作"。

| 元素 | 现有类名 | 说明 |
|------|---------|------|
| 按钮（实为 `<a>`） | `.open-app-btn` | 大按钮、主色、醒目；hover/pressed/focus-visible 三态清晰 |

**设计建议**：可配 App 图标或箭头 icon（内联 SVG）；按钮下方可加一行小字提示「手机端将自动唤起 App」。

### 3.5 元素 D：跨设备二维码（`.qr-box`）

**功能**：桌面端用户用手机 App 扫码完成授权（替代手动输入）。

| 元素 | 现有类名 | 说明 |
|------|---------|------|
| 二维码容器 | `.qr-box` | 白底卡片，居中 |
| 画布容器 | `.qr-render-wrap` | 240×240，二维码画布 `.qr-canvas` |
| 过期遮罩 | `.qr-expired-overlay` | 过期时半透明遮罩 + 「二维码已过期」 |
| 扫描提示 | `.qr-fallback` | 「使用 Mini-HBUT App 扫描上方二维码完成登录（桌面端）」 |
| 链接降级区 | `.qr-browser-fallback`：`.qr-browser-fallback-hint` + `.qr-browser-fallback-url` + `.qr-browser-fallback-copy` | 相机无法识别时复制链接到 App；复制按钮有「已复制」反馈态 |

**移动端规则**：≤560px 宽度时二维码区域默认隐藏（现有 CSS 行为），优先显示"打开 App"按钮。

### 3.6 元素 E：状态横幅（`.status-banner`）

**功能**：告知当前授权进度/结果。**同一布局承载 10 种状态**（文案已由代码固定，不能改语义）：

| 状态 | 现有类名 | 文案（固定） | 语义色 |
|------|---------|-------------|--------|
| LOADING | `.status-info` | 正在加载授权信息… | 信息（蓝） |
| WAITING_APP | `.status-info` | 请在 Mini-HBUT 中确认此次登录 | 信息（蓝） |
| APP_OPENED | `.status-info` | 已在 Mini-HBUT 中打开，请在 App 中确认此次登录 | 信息（蓝） |
| APPROVED | `.status-ok` | 授权已完成，正在返回… | 成功（绿） |
| REDIRECTING | `.status-ok` | 授权已完成，正在返回原应用… | 成功（绿） |
| DENIED | `.status-error` | 你已在 Mini-HBUT 中拒绝此次授权 | 失败（红） |
| EXPIRED | `.status-error` | 此次登录请求已过期，请回到原应用重新发起 | 失败（红） |
| INVALID | `.status-error` | 授权链接无效或已失效…（缺凭据时有专属文案） | 失败（红） |
| CLIENT_UNAVAILABLE | `.status-error` | 该应用当前不可用，请稍后再试 | 失败（红） |
| NETWORK_ERROR | `.status-error` | 网络连接中断，正在自动重试… | 失败（红） |

**现有符号前缀**：`⏳`（info）/ `✓`（ok）/ `⚠`（error），可沿用或设计更好的图形。

**重试按钮（可选出现）**：`.retry-btn` —— 仅 APPROVED + resume 失败时出现，文案「重新返回原应用」。

### 3.7 页面状态切换（设计时需覆盖的呈现差异）

1. **无详情阶段**（LOADING / INVALID / EXPIRED / DENIED / CLIENT_UNAVAILABLE / REDIRECTING / APPROVED / NETWORK_ERROR 无详情时）：页面**只有**状态横幅（没有卡片/按钮/二维码）。设计需保证单横幅的页面不空旷、不突兀。
2. **详情已加载**（WAITING_APP / APP_OPENED / NETWORK_ERROR 有详情）：完整布局（卡片+倒计时+按钮+二维码+横幅）。
3. 建议：状态横幅可以带图标 + 色块 + 建议动作（例如 EXPIRED 可提示"回到原应用重新发起"——文案已含此意）。

## 四、页面 2：帮助页 `/help`

**功能**：用户无法打开 App 时的排障说明。**安全红线：任何页面不得要求输入学校密码**，本页需明确声明。

**元素**：

| 元素 | 现有类名 | 说明 |
|------|---------|------|
| 页面容器 | `.card.auth-help` | 窄卡（≤560px） |
| 标题 | `h1` | 「无法打开 Mini-HBUT？」 |
| 步骤列表 | `ol.help-list` > `li`（`strong` 标题 + `p` 说明） | 现有 3 条：未安装 / 点击无反应 / 请求已过期 |
| 安全提示 | `.help-note` | 「本服务不会在任何网页要求你输入学校账号或密码，也不会在网页上批准权限；批准或拒绝请在 Mini-HBUT App 内完成」 |

## 五、页面 3：测试回调页 `/callback`（仅测试）

**功能**：授权完成后 Core 302 到此页并携带 `?code=`，页面展示授权码 + 换 token 的 curl 命令（测试用途，生产应用不会这样设计）。

**元素**：

| 元素 | 现有类名 | 说明 |
|------|---------|------|
| 测试横幅 | `.test-banner` | 🧪 测试环境声明 |
| 主标题 | `h1` | 「授权完成（测试）」 |
| 结果区 | `.callback-result`（成功 `.callback-success` / 失败 `.callback-error`） | 成功显示授权码 `.callback-code-value`；失败显示错误码 |
| 换 token 说明 | `p.callback-note` + `pre.callback-code` | curl 命令块（等宽字体、可横向滚动） |
| 警示 | `.callback-warn` | 「此授权码仅用于测试换取令牌，不会保存到任何地方」 |

**设计建议**：命令块使用深色代码块风格，授权码醒目可选中复制。

## 六、设计交付约定

1. **交付物**：一份完整的 CSS（覆盖 `app/globals.css` 全部内容，或提供覆盖追加文件）。可附带内联 SVG 图标（直接写在 CSS 中不现实——图标如需新增，请在文档中说明，我来加 DOM）。
2. **必须保留的类名**：上表所有类名是 JSX 中写死的，**不能改名**；你可以新增类名，但不能删除/重命名现有类。
3. **必须保留的行为**：`qr-box` 移动端隐藏、状态横幅 `role="status"` 语义、按钮 focus 样式。
4. **深色模式**：必须同时设计 `@media (prefers-color-scheme: dark)` 变体。
5. 设计完成后告诉我，我会：替换 CSS → 本地/云端构建 → 用浏览器逐状态截图核对 → 提交。

## 七、可供设计发挥的方向（建议，非强制）

- **品牌形象**：Header 图标 + 主按钮风格统一（圆角、渐变、描边任一体系）
- **应用卡片层级**：应用名最大，域名次之但明显（防钓鱼核心）
- **状态横幅**：可升级为带图标卡（成功=对勾圆、等待=脉冲点、失败=感叹号圆）
- **二维码区域**：圆角框 + 呼吸提示光效（注意不要影响扫码）
- **深浅双主题**：可做更精致的深色版（卡片内嵌层次、边框发光）
- **动效克制**：仅允许 loading 脉冲、按钮 hover 微交互、状态切换淡入（<300ms，不干扰轮询）
