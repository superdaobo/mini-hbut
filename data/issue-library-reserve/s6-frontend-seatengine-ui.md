## TL;DR

实现座位预约的**查询**界面（余量、开放时段、我的预约、规则说明）。
不含选座与提交（接口契约未抓到，见 S3 说明）。

## 需求描述

座位预约使用频率最高。第一版让用户能在 App 内看到座位预约的开放规则、
可约时段与自己的预约记录，把数据链路先跑通。

## 当前行为

前端无任何图书馆预约界面。

## 期望行为

## 已知事实（勘察产出）

### 关键规则（来自 `seatengine/index` 实测）

| 字段 | 值 | 含义 |
| --- | --- | --- |
| `reserveBeforeDay` | 1 | 提前 1 天可约 |
| `reserveBeforeTime` | `08:00` | **每天 08:00 放次日号** |
| `reserveDuration` | 4 | 预约时长（小时） |
| `reserveNumLimit` | 1 | 同时仅 1 个预约 |
| `violateTimes` / `violationLimitDay` / `violationLimitDuration` | 3 / 7 / 3 | 7 天内违约 3 次 → 停用 3 天 |
| `timeUnit` | 60 | 时间粒度（分钟） |
| `commonTimeConfig` | 08:00–22:00 | 每日开放时段 |
| `onlySupportsApiSignIn` | true | **签到只能走接口，无网页按钮** |

### 规则原文（`noticeContent` 摘录）

1. 按预约的座位号就坐和使用。
2. **应在预约起始时间后 20 分钟内完成签到**，否则视为违约。
3. 临时离开请使用"暂离"功能，**每日最多 3 次**。
4. 预约时间结束后自动签退。
5. **一周内违约达 3 次将被限制本周预约**；未按时签到、座位长时间未投入使用均视为违约。

### ⚠️ 时间必须用服务端时间

页面使用**服务端注入的当前时间**做开放判断：

```javascript
serverNow = new Date('<服务端注入的时间>')
```

本地时间模拟对其无效。前端展示"距离开放还有多久""今日是否已截止"时，
**必须使用后端返回的服务端时间**，否则会出现"本地显示可约但服务端已截止"的错位。
